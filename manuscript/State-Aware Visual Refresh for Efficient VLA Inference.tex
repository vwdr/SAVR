% =========================
% Abstract
% =========================

\begin{abstract}
\justifying
Vision language action models (VLAs) have improved language-conditioned robot manipulation, but their use in closed-loop control remains computationally expensive. Each control step can require a new visual encoding, even when consecutive observations differ only marginally. We propose State-Aware Visual Refresh (SAVR), a training-free inference controller that decides whether to refresh or reuse visual features using image change, robot state change and recent action change. The method is intentionally lightweight: it wraps around an existing VLA without changing the policy weights or action head. The experimental design compares SAVR with Full Refresh (FR), Periodic Refresh (PR) and Visual-Only Refresh (VOR), testing whether embodied state and action signals provide a more reliable basis for visual reuse than visual similarity alone.
\end{abstract}

\section{Introduction}

Vision language action models (VLAs) have made language-conditioned robot manipulation substantially more flexible. The RT-1 model showed that transformer-based robot policies can scale with broad robot datasets, while the RT-2 model connected vision language pretraining with action generation. The OpenVLA model later made this line of work more accessible by releasing an open 7B-parameter VLA trained on large-scale robot demonstrations using a Llama~2 backbone with DINOv2 and SigLIP visual features~\bcite{rt1,rt2,openvla}.

The cost of inference remains a practical obstacle. Closed-loop manipulation requires repeated policy calls, often at a frequency where small inefficiencies accumulate over an episode. Recent work has reduced this burden through compact policy design, faster fine-tuning, parallel action decoding, action tokenization and system-level pipelining~\bcite{tinyvla,openvlaoft,fast,actionflow}. These methods make the point that VLA capability alone is insufficient if inference is too slow for deployment.

This paper asks when visual information should be recomputed during closed-loop control. Consecutive observations in manipulation are frequently redundant because the instruction is fixed and the scene often changes gradually, yet global visual similarity can be misleading. Near contact, during grasping or around gripper closure, small changes in robot state may carry more control significance than the apparent change in the image. A visual-only refresh rule may therefore reuse cached information at precisely the steps where the policy needs updated perception.

We propose State-Aware Visual Refresh (SAVR), a training-free inference controller for deciding whether to refresh or reuse visual features at each control step. The SAVR controller combines visual change with changes in robot state and recent policy output. Rather than modifying the VLA, SAVR tests whether embodied state and action dynamics can make visual reuse safer than fixed-rate or visual-only refresh policies.

\section{Related Work}

\subsection{Foundation robot policies and VLA models}

The RT-1 model demonstrated that transformer-based robot policies can scale with large robot datasets, and the RT-2 model extended this trajectory by transferring vision language knowledge into robot action generation~\bcite{rt1,rt2}. The OpenVLA model then provided an open VLA trained on large-scale robot demonstrations~\bcite{openvla}. These systems define the setting studied here: a language-conditioned policy repeatedly maps visual observations and robot state into actions during closed-loop execution.

\subsection{Action-side and system-side efficiency}

A substantial portion of VLA efficiency work reduces the cost of action generation or deployment. The TinyVLA model pursues efficiency through a compact multimodal policy design~\bcite{tinyvla}. The OpenVLA-OFT method improves OpenVLA adaptation through parallel decoding, action chunking, continuous action prediction and an L1 regression objective~\bcite{openvlaoft}. The FAST method changes the action representation through frequency-space action sequence tokenization~\bcite{fast}. The ActionFlow system targets deployment through pipelined execution for faster on-device action generation~\bcite{actionflow}. These methods are important, but they leave open a separate source of cost: repeated visual recomputation across nearby control steps.

\subsection{Visual redundancy and caching}

Visual-side efficiency methods more directly address redundancy in visual observations or visual tokens. The VLA-Cache method is the closest prior work to SAVR because it identifies minimally changed visual tokens across adjacent frames and reuses their computation through KV-cache reuse~\bcite{vlacache}. The VLA-IAP method also reduces inference cost by pruning visual tokens according to interaction alignment~\bcite{vlaiap}. These approaches support the premise that visual computation in manipulation is often redundant. In this paper, we explore when that redundancy is safe to exploit.

\subsection{Adaptive computation}

The AC$^2$-VLA method studies adaptive computation using action context, observation context and selective execution~\bcite{ac2vla}. It suggests that action context can carry information about computational need. The SAVR controller adopts this insight in a narrower form by testing whether robot state and recent action change improve the specific decision of refreshing visual features.

\section{Problem Formulation}

Consider a language-conditioned manipulation episode of length $T$. Let $x$ denote the fixed language instruction, $o_t$ the camera observation at control step $t$, $s_t$ the robot state and $\pi_{\theta}$ the base VLA policy. The robot state may include end-effector pose, gripper state, joint positions or other proprioceptive variables available to the policy. At each step, the policy produces an action $\hat{a}_t$.

The visual refresh problem asks whether the current visual representation should be recomputed or whether a cached representation from an earlier step is sufficient. The binary refresh decision is defined as
\begin{equation}
r_t =
\begin{cases}
1, & \text{refresh visual features at step } t, \\
0, & \text{reuse cached visual features at step } t.
\end{cases}
\label{eq:refresh_decision}
\end{equation}

In \beqref{eq:refresh_decision}, $r_t$ is the refresh decision at control step $t$. A value of $r_t=1$ triggers visual recomputation, while $r_t=0$ reuses cached visual features.

This definition places dense inference, fixed-rate refresh and adaptive refresh under the same decision framework. The paper can then compare policies by asking how often they choose to refresh, how much latency they save and whether the saved computation harms task success.

Let $\tau_t$ be the most recent step at or before $t$ where $r_{\tau_t}=1$. A refresh controller is a causal decision rule:
\begin{equation}
g_t : (o_t, o_{\tau_t}, s_t, s_{t-1}, \hat{a}_{t-1}, \hat{a}_{t-2}) \mapsto r_t .
\label{eq:gate_definition}
\end{equation}

In \beqref{eq:gate_definition}, $g_t$ denotes the controller at step $t$, $o_t$ is the current camera observation, $o_{\tau_t}$ is the observation from the most recent refreshed step, $s_t$ and $s_{t-1}$ are the current and previous robot states, $\hat{a}_{t-1}$ and $\hat{a}_{t-2}$ are the two most recent predicted actions and $r_t$ is the output refresh decision.

The value of \beqref{eq:gate_definition} is that it makes the refresh decision explicitly causal. The controller uses only present and past information, which matches the constraints of closed-loop execution. This also clarifies the intended contribution of SAVR: the decision is not based on future failure labels or retraining, but on signals already available during inference.

The objective is to reduce inference cost while maintaining task success relative to FR:
\begin{equation}
\min_{g} \ \mathbb{E}[C(g)]
\quad
\text{subject to}
\quad
\mathbb{E}[S(g)] \geq \mathbb{E}[S(\mathrm{FR})] - \epsilon .
\label{eq:optimization_objective}
\end{equation}

In \beqref{eq:optimization_objective}, $g$ is a refresh controller, $C(g)$ is deployment cost under $g$, $S(g)$ is task success under $g$, $\mathbb{E}[\cdot]$ denotes expectation over tasks, episodes or random seeds, $S(\mathrm{FR})$ is the task success of the FR baseline and $\epsilon$ is the maximum acceptable success decrease relative to FR.

This objective formalizes the central trade-off of the paper. Lower latency is not useful if it simply degrades manipulation success, and high success is less deployable if it requires full visual recomputation at every step. The constraint therefore treats FR as the performance reference and asks whether adaptive refresh can reduce cost while remaining within an acceptable success margin.

\subsection{Overview}

These signals determine whether the current observation is encoded or whether the cached representation is reused. \subsection{Refresh Signals}

The image-change signal compares the current observation with the most recent observation that was actually encoded:
\begin{equation}
\Delta_t^{\mathrm{img}}
=
\frac{1}{M}
\sum_{j=1}^{M}
\left\|
\operatorname{down}(o_t)^{(j)}
-
\operatorname{down}(o_{\tau_t})^{(j)}
\right\|_1 .
\label{eq:image_change}
\end{equation}

In \beqref{eq:image_change}, $\Delta_t^{\mathrm{img}}$ is the image-change score at control step $t$, $\operatorname{down}(\cdot)$ is a fixed downsampling operation, $o_t$ is the current camera observation, $o_{\tau_t}$ is the observation from the most recent refreshed step, $j$ indexes a downsampled image patch or region, $M$ is the number of patches or regions and $\|\cdot\|_1$ is the L1 distance.

The equation is included because visual reuse is only defensible when the cached visual representation remains close enough to the current scene. Comparing $o_t$ with $o_{\tau_t}$, rather than only $o_{t-1}$, is important because small frame-to-frame changes can accumulate over several reuse steps. The score therefore measures visual drift from the last representation that the VLA actually encoded.

The state-change signal measures how much the robot has moved since the previous control step:
\begin{equation}
\Delta_t^{\mathrm{state}}
=
\left\|
W_s(s_t - s_{t-1})
\right\|_2 .
\label{eq:state_change}
\end{equation}

In \beqref{eq:state_change}, $\Delta_t^{\mathrm{state}}$ is the robot-state-change score at control step $t$, $s_t$ is the current robot state, $s_{t-1}$ is the previous robot state, $W_s$ is a diagonal normalization matrix for state dimensions and $\|\cdot\|_2$ is the Euclidean norm.

The equation captures a limitation of image-only refresh rules. A robot may enter a more visually sensitive part of the task even when the camera frame changes little. End-effector displacement, joint motion or gripper-related changes can make the cached visual representation less reliable for action selection, so the state score acts as an embodied warning signal.

The action-change signal measures short-term variation in the policy output:
\begin{equation}
\Delta_t^{\mathrm{act}}
=
\left\|
W_a(\hat{a}_{t-1} - \hat{a}_{t-2})
\right\|_2 .
\label{eq:action_change}
\end{equation}

In \beqref{eq:action_change}, $\Delta_t^{\mathrm{act}}$ is the recent action-change score at control step $t$, $\hat{a}_{t-1}$ is the action predicted at the previous control step, $\hat{a}_{t-2}$ is the action predicted two control steps earlier, $W_a$ is a diagonal normalization matrix for action dimensions and $\|\cdot\|_2$ is the Euclidean norm.

The equation treats the policy output as a weak signal of task phase. Abrupt action changes may reflect grasp initiation, corrective motion, directional reversal or instability caused by stale perception. The action score is not assumed to be sufficient on its own; its role is to add a behavioral signal that may be missed by visual comparison alone.

\subsection{Refresh Rule}

Let $h_t=t-\tau_t$ be the number of steps since the last visual refresh. The SAVR controller refreshes the visual representation if any signal exceeds its threshold or if the cached representation has reached a maximum reuse horizon:
\begin{equation}
r_t =
\mathbb{I}
\left[
\Delta_t^{\mathrm{img}} > \gamma_{\mathrm{img}}
\ \vee\
\Delta_t^{\mathrm{state}} > \gamma_{\mathrm{state}}
\ \vee\
\Delta_t^{\mathrm{act}} > \gamma_{\mathrm{act}}
\ \vee\
h_t \geq H_{\max}
\right] .
\label{eq:savr_rule}
\end{equation}

In \beqref{eq:savr_rule}, $r_t$ is the binary refresh decision, $\mathbb{I}[\cdot]$ is the indicator function, $\Delta_t^{\mathrm{img}}$, $\Delta_t^{\mathrm{state}}$ and $\Delta_t^{\mathrm{act}}$ are the image, state and action change scores, $\gamma_{\mathrm{img}}$, $\gamma_{\mathrm{state}}$ and $\gamma_{\mathrm{act}}$ are their corresponding thresholds, $h_t$ is the number of control steps since the most recent refresh, $H_{\max}$ is the maximum allowed reuse horizon and $\vee$ denotes logical OR.

The rule is intentionally interpretable. Image change captures scene drift, state change captures embodied motion and action change captures policy-level instability. The horizon term prevents indefinite reuse even when the three change scores remain below threshold. This design is conservative: it favors refresh when any signal indicates that cached visual features may no longer be reliable.

If the refresh decision is positive, the current observation is encoded:
\begin{equation}
z_t = E_{\phi}(o_t).
\label{eq:refresh_features}
\end{equation}

In \beqref{eq:refresh_features}, $z_t$ is the visual representation used at control step $t$, $E_{\phi}$ is the visual encoder with parameters $\phi$ and $o_t$ is the current camera observation.

The equation defines the refresh branch of SAVR. When $r_t=1$, the controller pays the visual computation cost to obtain a representation aligned with the current observation. This branch preserves the behavior of dense VLA inference for steps judged to be visually or behaviorally important.

If the refresh decision is negative, the SAVR controller reuses the most recent cached representation:
\begin{equation}
z_t = z_{\tau_t}.
\label{eq:reuse_features}
\end{equation}

In \beqref{eq:reuse_features}, $z_t$ is the visual representation used at control step $t$ and $z_{\tau_t}$ is the cached visual representation from the most recent refreshed step $\tau_t$.

The equation defines the reuse branch. When $r_t=0$, the controller avoids visual recomputation and forwards the cached representation to the base VLA. The benefit is lower inference cost; the risk is that stale visual features may no longer support the correct action.

The base VLA then predicts the next action:
\begin{equation}
\hat{a}_t = \pi_{\theta}(x,z_t,s_t).
\label{eq:policy_output}
\end{equation}

In \beqref{eq:policy_output}, $\hat{a}_t$ is the predicted action at control step $t$, $\pi_{\theta}$ is the base VLA policy with parameters $\theta$, $x$ is the language instruction, $z_t$ is the visual representation selected by the refresh controller and $s_t$ is the robot state.

The equation shows that SAVR does not alter the base policy. Both refresh and reuse produce a visual representation $z_t$, which is then passed to the same VLA with the same language instruction and robot state. The method therefore isolates the effect of visual refresh scheduling rather than confounding it with model retraining or action-head changes.

\subsection{Comparison Policies}

The evaluation compares SAVR against three refresh policies. The FR baseline recomputes visual features at every step and serves as the dense reference. The PR baseline recomputes visual features every $k$ steps and tests whether a clock-based rule is sufficient. The VOR baseline uses only $\Delta_t^{\mathrm{img}}$ and removes the robot state and action terms. These baselines isolate the contribution of embodied signals to the refresh decision.

This structure is necessary because a favorable result for SAVR would be meaningful only if the state and action terms improve over both PR and VOR.

\subsection{Implementation Scope}

The SAVR controller is intended as a wrapper around an existing VLA when intermediate visual features or projected visual prefixes can be cached. For a single-step policy, the gate is evaluated before each action prediction. For a chunked policy, the gate is evaluated whenever the policy would normally construct a new visual prefix for the next action window. This design keeps the method compatible with OpenVLA-style autoregressive policies and OpenVLA-OFT-style chunked policies~\bcite{openvlaoft}. The implementation should log refresh decisions, latency, task success, skipped refresh percentage and failure cases.
