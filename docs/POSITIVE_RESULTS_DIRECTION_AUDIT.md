# Positive-Results Direction Audit

**Date:** 2026-08-24  
**Status:** Research decision; implementation has not begun  
**Scope:** Select the most plausible novel continuation of SAVR while preserving the completed negative result.

## 1. Decision

The recommended continuation is **On-Policy Counterfactual Cache Routing (OPCCR)**: a lightweight, reject-capable router that decides whether scene-camera visual key/value (KV) state may be reused while wrist-camera state is refreshed. The router is trained on trajectories generated by the caching policy itself and supervised by paired full-refresh and cached-action outputs at every visited state.

This is the strongest candidate found under the project's three requirements:

1. **Novelty:** the proposed contribution is on-policy, intervention-induced data aggregation for cache routing—not caching itself, a visual-change threshold, or a previous-step confidence gate.
2. **Positive-result plausibility:** it combines a proven downstream accelerator with a fail-closed router, so efficiency and reliability can be traded continuously rather than depending on one brittle threshold.
3. **Relevance and impact:** it directly addresses the failure discovered by SAVR: a cache decision changes the robot action, which changes future observations and invalidates an offline or exogenous refresh rule.

Positive results cannot be guaranteed before evaluation. OPCCR is the highest-plausibility direction found after auditing the evidence and nearest work; it is not a promise of a favorable result.

## 2. What the completed experiments establish

| Finding | Evidence | Consequence |
|---|---:|---|
| Full refresh is a strong oracle | 100/100 SAVR calibration; 97/100 ACR Object evaluation | Preserve full refresh as the teacher and fail-closed fallback. |
| Whole-prefix reuse is behaviorally unstable | Best SAVR1: 52/100 success at 34.69% online visual skip | Do not revive whole-prefix caching or tune more thresholds. |
| Offline replay does not predict closed-loop reuse | 374/783 online reuse queries in the best SAVR1 population concealed per-camera threshold violations; first comparable reused action changed in 87/87 cases | Train and validate the gate on cache-induced trajectories, not only full-refresh traces. |
| Wrist-camera changes were the dominant hidden violation | 372 of the 374 concealed per-camera violations were wrist violations | Keep wrist information fresh in the first implementation. |
| Conservative scene-only reuse can preserve success | ACR: 29/30 success at 26.06% scene reuse | Multi-view asymmetry remains a useful reliability prior. |
| Scene-encoder reuse has too little end-to-end headroom | At fixed 26.06% reuse, the zero-overhead upper bound was only 1.6202% wall improvement | The new method must attack the downstream language-model computation. |
| Most latency is downstream | FR pilot: 1,061.21/1,267.44 ms residual downstream (83.7%); visual backbone plus projector 15.874% | Use decoder visual-KV reuse rather than only encoder-feature reuse. |
| Batching did not beat optimized FR | V3 wall ratio versus batched FR: 1.00226; visual CUDA reduction 8.4618% | Do not pursue paired-camera batching as the paper contribution. |
| CUDA graph execution is not a viable basis here | V10 downstream-only capture failed before correctness despite 7.6152 GiB headroom under the reservation cap | Do not depend on graph capture, model sharding, or a new timing methodology. |

The negative paper remains valid and immutable. OPCCR is a new method motivated by, rather than a reinterpretation of, those results.

## 3. Architecture and feasibility audit

OpenVLA-OFT places projected scene and wrist tokens into the language-model sequence before proprioception and action decoding. The pinned implementation uses one language-model pass for the continuous action head. Therefore visual KV state exists across the decoder layers and is a direct target for reuse.

The official VLA-Cache implementation already integrates with OpenVLA-OFT and performs layer-adaptive visual-token KV reuse. It therefore supplies a practical accelerator substrate, not the proposed novelty. A rough BF16 KV estimate for 512 visual tokens, 32 layers, two K/V tensors, and hidden size 4096 is about 0.25 GiB before implementation overhead. OpenVLA-OFT reports approximately 16 GiB for LIBERO inference, so a single 24 GiB GPU is plausible; the first bounded microbenchmark must verify the actual peak before any experiment.

No multi-GPU sharding, CUDA graphs, model retraining, or system-wide changes are required by the proposal.

## 4. Nearest-work collision audit

| Work | What it already contributes | Why it rules out a simpler idea | Remaining distinction of OPCCR |
|---|---|---|---|
| VLA-Cache (NeurIPS 2025) | Task-relevant, temporal and layer-adaptive visual-token KV reuse | KV reuse itself is not novel | Learns whether to serve cache at cache-induced states using paired FR/cached supervision. |
| LAC (2026 preprint) | Learned adaptive token selector and cache ratio using current frames and optical flow | A generic learned visual cache selector is not novel | Explicit on-policy aggregation, full-refresh counterfactual teacher, reject/OOD gate, and asymmetric camera policy. |
| Gated VLA-Cache (2026 preprint) | Previous-step logit-margin gate for KV reuse | Confidence-gated KV caching is not novel | Predicts current intervention risk from current observations/state and training distributions created by caching. |
| The Gate, Not the Cache (2026 preprint) | Shows sparse self-harvested gates can collapse; proposes dense actuation-slack refresh | A sparse self-labeling gate or fixed dense refresh schedule is not enough | Collects labels at every visited state from paired FR/cached outputs and retains mandatory clean refresh safeguards. |
| Action-JND (2026 preprint) | Learns action-tolerance estimates from perturbed clean deep features | Learned action sensitivity alone is not novel | Targets closed-loop policy-induced states and the binary serve/refresh intervention rather than clean-feature perturbation tolerance. |
| Selective Perception (2026 preprint) | Multi-view routing | Camera routing alone is not novel | Asymmetry is a fixed prior; the contribution is on-policy counterfactual cache routing. |
| AC2-VLA / SpecVLA / ActionCache | Action-context compute allocation, speculative chunking, and action caching | Adaptive chunking/action reuse is already crowded and changes the project focus | Keeps the work specifically about reliable visual-state reuse in VLA inference. |
| DAgger and ThriftyDAgger | On-policy dataset aggregation and selective expert intervention | On-policy aggregation is established generally | Applies the principle to cache interventions and paired VLA compute paths, not imitation-policy learning. |

An exact-phrase and concept search found no paper that combines all four defining elements: cache-induced on-policy collection, paired current-state FR/cached counterfactual labels, reject-capable cache routing, and asymmetric scene/wrist KV reuse. This supports **provisional novelty**, not proof. A new collision search is mandatory immediately before manuscript submission because this area is moving quickly.

## 6. Claim boundary

If the frozen evaluation passes, the paper may claim that on-policy counterfactual cache routing improves the reliability–efficiency frontier over full refresh and existing cache gates on the evaluated OpenVLA-OFT/LIBERO setting.

It must not claim:

- formal robot safety;
- universal VLA generalization;
- novelty of KV caching, multi-view asymmetry, DAgger, or uncertainty rejection individually;
- a positive result selected after seeing the final holdout;
- superiority outside the tested checkpoints, tasks, hardware, and cache implementation.
